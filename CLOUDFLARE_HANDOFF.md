# публикация сайта через github и cloudflare pages

## задание следующему агенту

владелец разрешил создать репозиторий и опубликовать этот сайт через cloudflare из github. код уже загружен в публичный репозиторий:

https://github.com/Dronnn/andrey-maier-digital

нужно создать или настроить **cloudflare pages с git integration**, дождаться успешного production deployment и вернуть владельцу рабочую ссылку `*.pages.dev`. дизайн и тексты сайта менять не нужно.

на момент передачи у предыдущего агента работал github от аккаунта `Dronnn`. доступа к cloudflare не было: локальная авторизация wrangler истекла, активного подключения cloudflare в composio не было. cloudflare-проект для этого экспорта не создавался.

## 1. проверь доступ и существующие проекты

проверь доступ к нужному аккаунту cloudflare и наличие pages-проекта, уже связанного с этим репозиторием. если он есть, продолжи его настройку; повторный проект не создавай. предполагаемое имя нового проекта — `andrey-maier-digital`; если имя занято, выбери доступное и сообщи фактическое.

используй собственное действующее подключение cloudflare. при необходимости обнови авторизацию обычным способом. не запрашивай у владельца токены в переписке и не записывай секреты в репозиторий.

## 2. подключи github

в cloudflare dashboard открой workers & pages, затем создание приложения, раздел pages и импорт существующего git-репозитория. выбери github и `Dronnn/andrey-maier-digital`.

cloudflare workers & pages github app должна быть установлена и авторизована для аккаунта владельца и иметь доступ к этому репозиторию. если приложение видит только выбранные репозитории, добавь именно этот репозиторий в разрешённые.

важно создать проект с git integration сразу. обычный direct upload через wrangler сам по себе не подключает автоматическую публикацию из github.

## 3. укажи параметры

| параметр | значение |
|---|---|
| production branch | `main` |
| framework preset | `None` |
| root directory | корень репозитория / пустое поле |
| build command | `exit 0` |
| build output directory | `public` |
| environment variables | не нужны |

это готовые статические файлы. `npm install`, фреймворк, worker, база данных и секреты для работы сайта не требуются. публиковать нужно содержимое `public`, где находится `index.html`.

если используешь cloudflare api, создай pages project с github source configuration и этими параметрами. предварительно проверь действующую установку cloudflare github app. не подменяй git integration разовой загрузкой файлов.

## 4. проверь результат

дождись успешной production-публикации из ветки `main`. проверь, что deployment соответствует текущему коммиту репозитория.

на опубликованной странице проверь:

- главная страница открывается, стили, шрифты, портрет и favicon загружаются;
- три заголовка сменяются плавно, бегущая строка медленно и непрерывно движется влево;
- раскрываются все семь услуг, меню и внутренние ссылки работают;
- контакты заполнены; телефон `+7 918 256-03-80`, почта `hello@mrmaier.com`, telegram `https://t.me/AndreasRobertMaier`;
- в html и response headers нет `noindex`, а `robots.txt` разрешает индексирование;
- на телефоне и компьютере нет перекрытия текста и горизонтальной прокрутки.

портрет отображается через svg viewport: он использует точные пиксели согласованного макета из `public/assets/andrey-portrait.png`. не заменяй весь раздел картинкой и не перерисовывай лицо.

## 5. заверши передачу

сообщи владельцу фактический адрес сайта и что автоматическая публикация из `main` включена. верни ссылку на pages-проект, если интерфейс её предоставляет.

произвольный custom domain не назначай. `mrmaier.com` уже используется другим сайтом, его dns и текущий хостинг не меняй без указания владельцем конкретного домена для этого лендинга.

после определения конечного адреса добавь корректные абсолютные `og:url`, `og:image` и canonical. текущий относительный `og:image` находится в `public/assets/og-cover.svg`; при необходимости отдельной задачей подготовь подходящее изображение для социальных сетей. это не блокирует публикацию страницы.
